How Multi-Tenant Aggregation Works
Every store runs on its own isolated PostgreSQL database. The background aggregation engine extracts transaction changes via outbox tables and maintains pre-aggregated summary tables. Analytical queries are served with millisecond latencies without touching the tenant databases.

Core Architecture & Isolation Guarantees
  • Strict Physical Isolation: Tenant stores have distinct PostgreSQL databases. Credentials never span across stores.
  • Zero Transaction Interference: Analytical reporting queries never lock or scan the primary transactional databases.
  • Outbox Atomic Consistency: Changes are captured inside the primary ACID transaction, eliminating dual-write race conditions.
  • Deterministic Time Snapping: Rollups snap to whole-hour and whole-day boundaries, guaranteeing repeatable metrics.
